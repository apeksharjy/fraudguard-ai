The Critical Problem in Digital Payments

Digital transactions are instantaneous, but safety guidance is broken.

❌ Opaque AI Decisions

Legacy fraud filters return vague binary flags (Accepted/Declined) without explaining *why* a payment triggered suspicion, causing user panic and confusion.

❌ LLM Hallucinations

Generic chatbots invent bank claims or request confidential secrets like UPI PINs, passwords, and OTPs, amplifying security risks.

❌ Post-Transaction Delays

Fraud checks often trigger after money moves, making fund recovery nearly impossible in instant payment networks.

❌ Alert Fatigue

Users ignore warnings that don't provide practical, verified steps to verify legitimate merchants safely.

End-to-End System Architecture

Strict separation of concerns with server-side ML and rules execution

🖥️ React 19 + Vite Frontend

  • Dark cyber/fintech theme with accessible WCAG contrast.
  • Real-time input validation, responsive presets, and interactive charts.
  • Prominent prototype disclaimers across all views.

⚙️ FastAPI + Python Backend

  • Pydantic v2 strict input boundary validation.
  • Multi-signal Rules Engine generating transparent reason codes.
  • Calibrated Random Forest Classifier (0-100 score).
  • SQLite audit trail with user feedback recording.

🛡️ Hybrid Scoring Logic

Combines ML anomaly probabilities with deterministic compound rules: high amounts (> $5,000), new device flags, midnight hours (23:00 - 04:00), and rapid retry bursts (> 3 attempts in 10 minutes) automatically produce documented risk levels.
